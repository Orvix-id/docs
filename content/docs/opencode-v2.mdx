# OpenCode V2 Manual Config

<Callout type="warn">
  **Use the plugin if you can.** `opencode plugin add @orvix-id/opencode` registers both Orvix
  providers, keeps the model list current and enables prompt caching for the Coding Plan. See
  [OpenCode Setup](/opencode). This page is for setups that cannot load plugins.
</Callout>

This config is for **OpenCode 2.x** only. OpenCode 1.x uses different field names; a 2.x block in a
1.x install (or the reverse) does not load, typically with `Unsupported package`.

## Pick the endpoint first

| You pay with | Base URL | Key scope | Provider ID below |
| --- | --- | --- | --- |
| Coding Plan or AI Plan | `https://api.orvix.id/coding/v1` | `coding:invoke` | `orvix-coding` |
| Orvix Credits | `https://api.orvix.id/v1` | `ai:invoke` | `orvix` |

Pointing a Coding Plan key at `/v1` bills Orvix Credits instead of the plan and fails with
`insufficient Orvix Credits` when the wallet is empty.

## Configure the provider

Edit `~/.config/opencode/opencode.json` (macOS/Linux) or `%APPDATA%\opencode\opencode.json`
(Windows). Merge into the existing file without removing other settings. Note the top-level key is
`providers` (plural).

**Coding Plan:**

```json
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "orvix-coding": {
      "name": "Orvix Coding",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://api.orvix.id/coding/v1",
        "apiKey": "{env:ORVIX_CODING_API_KEY}"
      },
      "models": {
        "deepseek-v4.1-flash": {
          "modelID": "orvix/deepseek-v4.1-flash",
          "name": "DeepSeek V4.1 Flash (Orvix Coding)",
          "capabilities": {
            "tools": true,
            "input": ["text", "image"],
            "output": ["text"]
          }
        }
      }
    }
  }
}
```

**Orvix Credits:** the same block with provider ID `orvix`, base URL `https://api.orvix.id/v1`,
`"apiKey": "{env:ORVIX_API_KEY}"`, and models from `GET /v1/models`.

OpenCode 2.x uses `providers`, `package`, `settings`, `modelID` and `capabilities`. Do not mix in the
1.x fields `provider`, `npm`, `options`, `id` or `modalities`.

## Store the key

Store the key in the background service environment so an already-running service picks it up:

```bash
opencode service set env ORVIX_CODING_API_KEY "orv-sk_live_..."
opencode service get   # confirm it is set, without printing it elsewhere
```

## Validate and reload

```bash
python3 -m json.tool ~/.config/opencode/opencode.json
opencode reload
opencode models
```

Open `/models` and pick the model. The selector reads `orvix-coding/deepseek-v4.1-flash`: the first
part is the provider ID, `modelID` is what is sent to Orvix.

## Add more models

List the models your key can use, then add each one under `models`:

```bash
curl https://api.orvix.id/coding/v1/models -H "Authorization: Bearer $ORVIX_CODING_API_KEY"
```

Keep the full `orvix/` prefix in `modelID`. Set `capabilities.input` to `["text", "image"]` only for
models that accept images. Image and video generation models do not belong in a chat provider.

## Limits of manual config

Without the plugin, OpenCode does not send `session_id`, so Coding Plan requests still bill to the
plan but skip the prompt cache: every turn pays for the full prompt. The model list also does not
update when the plan's lineup changes.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Unsupported package` | The config is for the other OpenCode version. Check `opencode --version`, or use the plugin. |
| `insufficient Orvix Credits` with a Coding Plan | The base URL is `/v1`. Use `https://api.orvix.id/coding/v1`. |
| Missing Authorization header | Run `opencode service get`, confirm the key variable is set, restart the service. |
| `401 coding:invoke scope required` | Create a key with the **Orvix Coding** scope. |
| No BYOK route | Use the full model ID beginning with `orvix/` in `modelID`. |

More: [Coding Plan Setup](/coding-plan#troubleshooting).
