# Models

## List models

`GET /v1/models`

Returns all models available to your project based on your configured providers.

### Request

```bash
curl https://api.orvix.id/v1/models \
  -H "Authorization: Bearer orv-sk_live_..."
```

### Response

```json
{
  "object": "list",
  "data": [
    {
      "id": "gpt-4.1-mini",
      "object": "model",
      "created": 1720000000,
      "owned_by": "openai"
    },
    {
      "id": "claude-sonnet-4-20250514",
      "object": "model",
      "created": 1720000000,
      "owned_by": "anthropic"
    },
    {
      "id": "orvix/gpt-4.1",
      "object": "model",
      "created": 1720000000,
      "owned_by": "orvix"
    }
  ]
}
```

## Model ID format

Model IDs follow the provider's original naming convention. Orvix supports two funding modes:

{/* The two-column table reserved for a compact overview */}

| Mode | Prefix | Billing | How it works |
|---|---|---|---|
| **BYOK** | *(none)* | Your provider bill | You bring your own API keys — Orvix routes traffic through them |
| **Orvix Managed** | `orvix/` | Orvix Credits | Orvix handles the provider relationship — no keys needed from you |

---

### BYOK — Bring Your Own Key

BYOK lets you use **your own API keys** for any supported provider. You keep full control of your provider accounts while Orvix acts as a unified routing layer.

**How it works:**

1. Add your provider API keys in the [Orvix Platform](https://platform.orvix.id/providers) (for example, an OpenAI key, an Anthropic key, or a Gemini key).
2. Call the model using its **native ID** — no prefix needed.
3. Orvix routes the request to the matching provider using the key you configured.

**Example — calling GPT‑4.1 Mini with your own OpenAI key:**

```bash
curl https://api.orvix.id/v1/chat/completions \
  -H "Authorization: Bearer orv-sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

Because the model ID is `gpt-4.1-mini` (no `orvix/` prefix), Orvix looks up your configured OpenAI key and forwards the request. You pay OpenAI directly — Orvix does **not** add any markup.

> **Supported BYOK providers:** `openai`, `anthropic`, `gemini`, `deepseek`, `openrouter`, `ollama`, and any `custom` endpoint — [see full list below](#supported-providers).

---

### Orvix Managed Models

Models prefixed with `orvix/` are **fully managed by Orvix**. You don't need your own provider keys — Orvix owns and maintains the underlying provider accounts and bills you through **Orvix Credits**.

**How it works:**

1. Top up Orvix Credits from the [Platform](https://platform.orvix.id/billing).
2. Call any model prefixed with `orvix/`.
3. The `orvix/` prefix is stripped internally — `orvix/gpt-4.1` resolves to the managed `gpt-4.1` plan behind the scenes.

**Example:**

```bash
curl https://api.orvix.id/v1/chat/completions \
  -H "Authorization: Bearer orv-sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "orvix/gpt-4.1",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

**When to use Orvix Managed Models:**

- You don't want to manage provider API keys or billing relationships.
- You need a single, consolidated bill through Orvix Credits.
- You want instant access to models without signing up for each provider separately.

**When to use BYOK:**

- You already have API keys with providers and want to keep using them.
- You need specific rate limits or negotiated pricing with a provider.
- You want your usage to appear on the provider's own dashboard and billing.

## `orvix/auto` — let Orvix pick the model

Managed models span a wide price range. Sending every request to the most
capable one overpays for the easy ones; sending everything to the cheapest
gives poor answers on the hard ones. `orvix/auto` reads each request and picks
a model for it.

```bash
curl https://api.orvix.id/v1/chat/completions \
  -H "Authorization: Bearer orv-sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "orvix/auto",
    "messages": [{"role": "user", "content": "Translate to French: good morning"}]
  }'
```

### What it looks at

Selection is based on the shape of the request, not a separate model call — so
it adds no latency and costs nothing on top.

| Signal | Effect |
|---|---|
| Function tools present | Highest tier — tool loops need a capable model |
| Very large context, or a long conversation | Highest tier |
| Wording like "debug", "why does", "step by step", "trade-off" | Highest tier |
| A fenced code block | Middle tier |
| Short prompt, or "summarize" / "translate" / "classify" | Cheapest tier |

### Knowing what you were charged for

`orvix/auto` never appears in a response. The `model` field names the model
that actually ran, and two headers explain the choice:

```http
x-orvix-auto-tier: heavy
x-orvix-auto-reason: tools_requested
```

So a response to `orvix/auto` might come back with
`"model": "orvix/gpt-5.6-terra"` — that is the model you are billed for, at its
normal published rate. `orvix/auto` adds no markup; it only decides which rate
applies.

<Callout type="warn">
  Because the chosen model varies with the request, so does the cost. A request
  that trips a "highest tier" signal is billed at that model's rate. If you need
  a predictable per-request price, name a model directly instead.
</Callout>

### When not to use it

- You need every request to hit one specific model (evaluations, reproducibility).
- You have a fixed budget per request and cannot tolerate the variance.
- Your prompts are unusual enough that the signals above misread them — the
  `x-orvix-auto-reason` header tells you when this is happening.

## Supported providers

| Provider | Default base URL |
|---|---|
| `openai` | `https://api.openai.com/v1` |
| `anthropic` | `https://api.anthropic.com/v1` |
| `gemini` | `https://generativelanguage.googleapis.com/v1beta` |
| `deepseek` | `https://api.deepseek.com/v1` |
| `openrouter` | `https://openrouter.ai/api/v1` |
| `ollama` | `http://localhost:11434/v1` |
| `custom` | *(configured base URL)* |

Provider credentials are configured per-project from the Orvix Platform.
