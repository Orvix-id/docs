# API Store

API Store exposes six Indonesian data products under `https://api.orvix.id/v1`. Use an Orvix project API key with a product read scope or `api_store:all`.

```bash
curl https://api.orvix.id/v1/regions/provinces \
  -H "Authorization: Bearer $ORVIX_API_KEY"
```

## Products and scopes

| Product | Product ID | Scope | Source |
|---|---|---|---|
| Regional Indonesia | `regional-indonesia` | `regions:read` | API Wilayah Indonesia / Emsifa |
| Indonesia Schools | `schools-indonesia` | `schools:read` | Kemendikdasmen |
| National Holidays | `national-holidays` | `holidays:read` | SKB 3 Menteri |
| BMKG Indonesia | `bmkg-indonesia` | `bmkg:read` | BMKG open data |
| KBLI 2025 | `kbli-indonesia` | `kbli:read` | BPS KBLI 2025 |
| NIK Parser Indonesia | `nik-parser-indonesia` | `nik:read` | Orvix-hosted legacy administrative-code snapshot |

All six products are currently configured as free. Calls are still metered into project usage records for product, operation, latency, and status observability. Pricing is server-managed; clients should not infer billing from the body.

## Code examples

Each key needs the product scope listed above, or `api_store:all`. NIK endpoints use POST rather than the GET helper below so sensitive identifiers do not appear in URLs.

### JavaScript

```js
const apiKey = process.env.ORVIX_API_KEY;

async function apiStore(path, params = {}) {
  const url = new URL(`https://api.orvix.id${path}`);
  for (const [key, value] of Object.entries(params)) url.searchParams.set(key, String(value));
  const response = await fetch(url, { headers: { Authorization: `Bearer ${apiKey}` } });
  const body = await response.json();
  if (!response.ok) throw new Error(`${body.error?.code}: ${body.error?.message} (${body.meta?.request_id})`);
  return body;
}

const regions = await apiStore("/v1/regions/provinces");
const schools = await apiStore("/v1/schools", { search: "Jakarta", page: 1, size: 20 });
const holidays = await apiStore("/v1/holidays", { year: 2026 });
const weather = await apiStore("/v1/bmkg/weather", { adm4: "31.71.01.1001" });
const kbli = await apiStore("/v1/kbli/codes", { q: "software", page: 1, size: 20 });
```

### TypeScript

```ts
type ApiStoreResponse<T> = {
  data: T;
  meta: {
    request_id: string;
    product: string;
    operation: string;
    source: unknown | null;
    pagination: { page: number; page_size: number; total_items: number } | null;
    cache: unknown | null;
  };
};

async function apiStore<T>(path: string, params: Record<string, string | number> = {}): Promise<ApiStoreResponse<T>> {
  const url = new URL(`https://api.orvix.id${path}`);
  Object.entries(params).forEach(([key, value]) => url.searchParams.set(key, String(value)));
  const response = await fetch(url, {
    headers: { Authorization: `Bearer ${process.env.ORVIX_API_KEY}` },
  });
  const body = await response.json();
  if (!response.ok) throw new Error(`${body.error?.code}: ${body.error?.message} (${body.meta?.request_id})`);
  return body as ApiStoreResponse<T>;
}

const provinces = await apiStore<Array<{ id: string; name: string }>>("/v1/regions/provinces");
const schools = await apiStore<unknown[]>("/v1/schools", { search: "Jakarta", page: 1, size: 20 });
const holidays = await apiStore<unknown[]>("/v1/holidays", { year: 2026 });
const weather = await apiStore<unknown>("/v1/bmkg/weather", { adm4: "31.71.01.1001" });
const kbli = await apiStore<unknown[]>("/v1/kbli/codes", { q: "software", page: 1, size: 20 });
```

### Python

```python
import os
import requests

def api_store(path: str, params: dict | None = None) -> dict:
    response = requests.get(
        f"https://api.orvix.id{path}",
        params=params or {},
        headers={"Authorization": f"Bearer {os.environ['ORVIX_API_KEY']}"},
        timeout=15,
    )
    body = response.json()
    if not response.ok:
        error, meta = body.get("error", {}), body.get("meta", {})
        raise RuntimeError(f"{error.get('code')}: {error.get('message')} ({meta.get('request_id')})")
    return body

regions = api_store("/v1/regions/provinces")
schools = api_store("/v1/schools", {"search": "Jakarta", "page": 1, "size": 20})
holidays = api_store("/v1/holidays", {"year": 2026})
weather = api_store("/v1/bmkg/weather", {"adm4": "31.71.01.1001"})
kbli = api_store("/v1/kbli/codes", {"q": "software", "page": 1, "size": 20})
```

## Regional Indonesia

| Endpoint | Operation | Description |
|---|---|---|
| `GET /v1/regions/provinces` | `provinces.list` | List provinces |
| `GET /v1/regions/provinces/{province_id}` | `provinces.detail` | Province detail |
| `GET /v1/regions/provinces/{province_id}/regencies` | `regencies.lookup` | Regencies in a province |
| `GET /v1/regions/regencies/{regency_id}` | `regencies.lookup` | Regency detail |
| `GET /v1/regions/regencies/{regency_id}/districts` | `districts.lookup` | Districts in a regency |
| `GET /v1/regions/districts/{district_id}` | `districts.lookup` | District detail |
| `GET /v1/regions/districts/{district_id}/villages` | `villages.lookup` | Villages in a district |
| `GET /v1/regions/villages/{village_id}` | `villages.lookup` | Village detail |
| `GET /v1/regions/postal-codes?province=...&regency=...&district=...&village=...` | `postal-codes.search` | Exact hierarchical address search |
| `GET /v1/regions/postal-codes/{postal_code}` | `postal-codes.lookup` | Five-digit postal code lookup |

Region IDs contain digits. Postal codes must contain exactly five digits. Postal-code search requires all four address parameters (maximum 150 characters each). Matching is case-insensitive and tolerates common `Kota`, `Kabupaten`, `Kab.`, and `Administrasi` prefixes. Results may contain multiple locations. The postal dataset is hosted by Orvix and derived from `sooluh/kodepos` under Apache-2.0; no runtime request is sent to that service.

## NIK Parser Indonesia

NIK Parser Indonesia is a privacy-conscious structural parser for the 16-digit format used by Indonesian population identification numbers. It is useful for form validation, data normalization, and explaining encoded attributes. It does not contact Dukcapil, search for a person, prove ownership of a number, or perform KYC.

- **Scope:** `nik:read` or `api_store:all`
- **Price:** free
- **Content type:** `application/json`

| Endpoint | Operation | Description |
|---|---|---|
| `POST /v1/nik/parse` | `nik.parse` | Parse one 16-digit NIK structure |
| `POST /v1/nik/parse-batch` | `nik.parse_batch` | Parse 1–100 NIKs while preserving input order |

```bash
export NIK="your-16-digit-value"

curl https://api.orvix.id/v1/nik/parse \
  -X POST \
  -H "Authorization: Bearer $ORVIX_API_KEY" \
  -H "Content-Type: application/json" \
  --data "{\"nik\":\"$NIK\"}"
```

### Single request

The request body contains exactly one field:

```json
{
  "nik": "<16 ASCII digits>"
}
```

A successful response has this shape. Values below are illustrative and are not a sample identity or complete NIK:

```json
{
  "data": {
    "structurally_valid": true,
    "provinsi": "NAMA PROVINSI",
    "kota_kabupaten": "NAMA KOTA / KABUPATEN",
    "kecamatan": "Nama Kecamatan",
    "birth": {
      "date": "2000-01-01",
      "formatted": "01 Januari 2000",
      "age": 26,
      "zodiac": "Capricorn",
      "is_birthday_today": false,
      "year_is_inferred": true,
      "year_inference": "rolling_century"
    },
    "gender": {
      "code": "L",
      "label": "Laki-laki",
      "symbol": "♂"
    },
    "issues": []
  },
  "meta": {
    "request_id": "01...",
    "product": "nik-parser-indonesia",
    "operation": "nik.parse",
    "source": {
      "name": "Indonesia administrative code legacy snapshot",
      "coverage": { "provinces": 34, "regencies": 514, "districts": 7230 },
      "authoritative": false
    },
    "pagination": null,
    "cache": null
  }
}
```

### Response fields

| Field | Type | Meaning |
|---|---|---|
| `structurally_valid` | boolean | `true` only when the encoded date and all three administrative levels are structurally recognized |
| `provinsi` | string or `null` | Province name from the bundled snapshot |
| `kota_kabupaten` | string or `null` | City or regency name from the bundled snapshot |
| `kecamatan` | string or `null` | District name from the bundled snapshot |
| `birth` | object or `null` | Interpreted birth attributes; `null` when the encoded date is invalid |
| `birth.date` | string | Inferred ISO date (`YYYY-MM-DD`) |
| `birth.year_is_inferred` | boolean | Always identifies that the two-digit year required inference |
| `birth.year_inference` | string | Inference method; currently `rolling_century` |
| `gender.code` | string | `L` or `P`, based only on the encoded day convention |
| `issues` | array | Structural issues discovered without rejecting otherwise well-formed input |

The parser resolves administrative names, interprets the encoded gender/day, and infers the birth year with a rolling-century rule: a two-digit year not greater than the current two-digit year is placed in the 2000s; otherwise it is placed in the 1900s. This is an inference, not an authoritative birth record.

### Batch request

Batch parsing accepts 1–100 values and preserves their input order:

```bash
curl https://api.orvix.id/v1/nik/parse-batch \
  -X POST \
  -H "Authorization: Bearer $ORVIX_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"niks":["<16 ASCII digits>","invalid"]}'
```

```json
{
  "data": [
    { "data": { "structurally_valid": true }, "error": null },
    {
      "data": null,
      "error": {
        "code": "nik_invalid_format",
        "message": "NIK must contain exactly 16 digits"
      }
    }
  ],
  "meta": {
    "product": "nik-parser-indonesia",
    "operation": "nik.parse_batch"
  }
}
```

An invalid item does not fail its valid siblings. Duplicate values are processed independently and order is never changed.

### Structural issues and HTTP status

| Condition | HTTP | Result |
|---|---:|---|
| Missing single `nik` | 400 | `nik_required` |
| Single value is not exactly 16 ASCII digits | 400 | `nik_invalid_format` |
| Missing batch `niks` | 400 | `batch_required` |
| Batch contains 0 or more than 100 items | 400 | `batch_too_large` |
| Unknown province, city/regency, or district code | 200 | Partial data, `structurally_valid: false`, and an item in `issues` |
| Invalid encoded month or day | 200 | `birth: null`, `structurally_valid: false`, and an item in `issues` |

Possible issue codes include `province_not_found`, `regency_not_found`, `district_not_found`, `invalid_month`, and `invalid_day`. Each issue also contains a `field` pointing to the affected response field.

### Privacy and limitations

The response deliberately omits the submitted NIK, masked NIK, administrative codes, and serial number. Raw NIK values are not written to application logs, activity logs, analytics, or usage records. Usage metering stores operational metadata such as product, operation, status, and latency.

The parser never claims that an identity exists. It is **not** a Dukcapil service, identity verification, or KYC check. The bundled non-authoritative legacy snapshot covers 34 provinces, 514 regencies, and 7,230 districts. It does not include the four newer Papua provinces and must not be treated as complete or current national coverage. No runtime network lookup is made for NIK parsing.

Structurally parseable input returns HTTP 200. Invalid dates or unknown administrative codes appear in `data.issues` and set `structurally_valid` to `false`, while available partial region data remains present. Invalid format returns `nik_invalid_format`. Batch item errors are isolated inside each item and do not fail valid siblings.

## Indonesia Schools

`GET /v1/schools?page=1&size=20&search=Jakarta` uses operation `schools.list`.

| Query | Default | Constraint |
|---|---:|---|
| `page` | `1` | 1–100,000 |
| `size` | `20` | 1–100 |
| `search` | empty | Maximum 100 characters |

Pagination is returned in `meta.pagination`. `GET /v1/schools/{npsn}` uses `schools.detail`; NPSN must contain exactly eight ASCII letters or digits. A missing school returns `404` and `not_found`.

## National Holidays

| Endpoint | Operation | Description |
|---|---|---|
| `GET /v1/holidays?year=2026` | `holidays.list` | Published holidays for a year |
| `GET /v1/holidays?year=2026&kind=cuti_bersama` | `holidays.list` | Filter `libur_nasional` or `cuti_bersama` |
| `GET /v1/holidays/2026-12-25` | `holidays.check` | Check a `YYYY-MM-DD` date |
| `GET /v1/holidays/next?from=2026-10-01` | `holidays.next` | First holiday on or after a date |

`year` must be 2000–2100. A valid but unpublished year returns `dataset_not_available`, not an empty list.

## BMKG Indonesia

| Endpoint | Operation | Cache behavior |
|---|---|---|
| `GET /v1/bmkg/earthquakes/latest` | `bmkg.earthquakes` | 60 seconds |
| `GET /v1/bmkg/earthquakes/felt` | `bmkg.felt` | 60 seconds |
| `GET /v1/bmkg/weather?adm4=31.71.01.1001` | `bmkg.weather` | 1 hour; stale data may be served for up to 6 hours during an outage |

`adm4` is a four-part numeric level-four region code. Cache state is explicit in `meta.cache`.

## KBLI 2025

| Endpoint | Operation | Description |
|---|---|---|
| `GET /v1/kbli/categories` | `kbli.categories` | Top-level categories |
| `GET /v1/kbli/codes` | `kbli.list` | Paginated code directory |
| `GET /v1/kbli/codes/{code}` | `kbli.detail` | One 1–5 digit code |

List parameters: `page` defaults to 1 (maximum 10,000), `size` defaults to 20 (maximum 100), `level` is 1–5, `parent` filters by parent code, and `q` searches titles with a 100-character maximum.

## Success contract

```json
{
  "data": [],
  "meta": {
    "request_id": "01...",
    "product": "schools-indonesia",
    "operation": "schools.list",
    "source": null,
    "pagination": { "page": 1, "page_size": 20, "total_items": 123 },
    "cache": null
  }
}
```

`source`, `pagination`, and `cache` are always present and `null` when not applicable. The `x-request-id` header repeats `meta.request_id`.

External keys are recursively normalized to `snake_case` while values remain unchanged. For example, BMKG `Infogempa` becomes `data.info_gempa`, and `DateTime` becomes `date_time`.

## Error contract

API Store errors differ from OpenAI-compatible AI errors:

```json
{
  "error": { "code": "upstream_timeout", "message": "Region provider timed out" },
  "meta": {
    "request_id": "01...",
    "product": "regional-indonesia",
    "operation": "provinces.list",
    "upstream": { "classification": "timeout" }
  }
}
```

`meta.upstream` is always present and is `null` for validation, authentication, metering, local-dataset, and not-found errors. Upstream classifications are `timeout`, `unavailable`, or `invalid_response`. Raw upstream bodies and internal errors are never exposed.

Common codes: `invalid_request_error`, `insufficient_balance`, `metering_error`, `not_found`, `dataset_not_available`, `dataset_error`, `upstream_timeout`, `upstream_unavailable`, and `upstream_error`.

## Migrating from the legacy response

- Read records from `data`, not the response root.
- Read attribution, pagination, and cache state from `meta.source`, `meta.pagination`, and `meta.cache`.
- Pagination fields are `page`, `page_size`, and `total_items`.
- Replace external casing such as `Infogempa` and `DateTime` with `info_gempa` and `date_time`.
- Read failures from `error.code` and `error.message`; include `meta.request_id` in support requests.
