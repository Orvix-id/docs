# API Store

API Store menyediakan enam produk data Indonesia di `https://api.orvix.id/v1`. Gunakan API key project Orvix dengan scope baca produk atau `api_store:all`.

```bash
curl https://api.orvix.id/v1/regions/provinces \
  -H "Authorization: Bearer $ORVIX_API_KEY"
```

## Produk dan scope

| Produk | Product ID | Scope | Sumber |
|---|---|---|---|
| Regional Indonesia | `regional-indonesia` | `regions:read` | API Wilayah Indonesia / Emsifa |
| Indonesia Schools | `schools-indonesia` | `schools:read` | Kemendikdasmen |
| National Holidays | `national-holidays` | `holidays:read` | SKB 3 Menteri |
| BMKG Indonesia | `bmkg-indonesia` | `bmkg:read` | Data terbuka BMKG |
| KBLI 2025 | `kbli-indonesia` | `kbli:read` | BPS KBLI 2025 |
| NIK Parser Indonesia | `nik-parser-indonesia` | `nik:read` | Snapshot legacy kode administrasi yang di-host Orvix |

Keenam produk saat ini dikonfigurasi gratis. Pemanggilan tetap dicatat ke usage project agar produk, operation, latensi, dan status dapat diobservasi. Harga dikelola server; client tidak boleh menyimpulkan billing dari body.

## Contoh kode

Key harus memiliki scope produk terkait atau `api_store:all`. Endpoint NIK memakai POST, bukan helper GET di bawah, agar identifier sensitif tidak muncul di URL.

### JavaScript

```js
const apiKey = process.env.ORVIX_API_KEY;

async function apiStore(path, params = {}) {
  const url = new URL(`https://api.orvix.id${path}`);
  for (const [key, value] of Object.entries(params)) url.searchParams.set(key, String(value));
  const response = await fetch(url, { headers: { Authorization: `Bearer ${apiKey}` } });
  const body = await response.json();
  if (!response.ok) throw new Error(`${body.error?.code}: ${body.error?.message} (${body.meta?.request_id})`);
  return body;
}

const wilayah = await apiStore("/v1/regions/provinces");
const sekolah = await apiStore("/v1/schools", { search: "Jakarta", page: 1, size: 20 });
const libur = await apiStore("/v1/holidays", { year: 2026 });
const cuaca = await apiStore("/v1/bmkg/weather", { adm4: "31.71.01.1001" });
const kbli = await apiStore("/v1/kbli/codes", { q: "perangkat lunak", page: 1, size: 20 });
```

### TypeScript

```ts
type ApiStoreResponse<T> = {
  data: T;
  meta: {
    request_id: string;
    product: string;
    operation: string;
    source: unknown | null;
    pagination: { page: number; page_size: number; total_items: number } | null;
    cache: unknown | null;
  };
};

async function apiStore<T>(path: string, params: Record<string, string | number> = {}): Promise<ApiStoreResponse<T>> {
  const url = new URL(`https://api.orvix.id${path}`);
  Object.entries(params).forEach(([key, value]) => url.searchParams.set(key, String(value)));
  const response = await fetch(url, {
    headers: { Authorization: `Bearer ${process.env.ORVIX_API_KEY}` },
  });
  const body = await response.json();
  if (!response.ok) throw new Error(`${body.error?.code}: ${body.error?.message} (${body.meta?.request_id})`);
  return body as ApiStoreResponse<T>;
}

const provinsi = await apiStore<Array<{ id: string; name: string }>>("/v1/regions/provinces");
const sekolah = await apiStore<unknown[]>("/v1/schools", { search: "Jakarta", page: 1, size: 20 });
const libur = await apiStore<unknown[]>("/v1/holidays", { year: 2026 });
const cuaca = await apiStore<unknown>("/v1/bmkg/weather", { adm4: "31.71.01.1001" });
const kbli = await apiStore<unknown[]>("/v1/kbli/codes", { q: "perangkat lunak", page: 1, size: 20 });
```

### Python

```python
import os
import requests

def api_store(path: str, params: dict | None = None) -> dict:
    response = requests.get(
        f"https://api.orvix.id{path}",
        params=params or {},
        headers={"Authorization": f"Bearer {os.environ['ORVIX_API_KEY']}"},
        timeout=15,
    )
    body = response.json()
    if not response.ok:
        error, meta = body.get("error", {}), body.get("meta", {})
        raise RuntimeError(f"{error.get('code')}: {error.get('message')} ({meta.get('request_id')})")
    return body

wilayah = api_store("/v1/regions/provinces")
sekolah = api_store("/v1/schools", {"search": "Jakarta", "page": 1, "size": 20})
libur = api_store("/v1/holidays", {"year": 2026})
cuaca = api_store("/v1/bmkg/weather", {"adm4": "31.71.01.1001"})
kbli = api_store("/v1/kbli/codes", {"q": "perangkat lunak", "page": 1, "size": 20})
```

## Regional Indonesia

| Endpoint | Operation | Keterangan |
|---|---|---|
| `GET /v1/regions/provinces` | `provinces.list` | Daftar provinsi |
| `GET /v1/regions/provinces/{province_id}` | `provinces.detail` | Detail provinsi |
| `GET /v1/regions/provinces/{province_id}/regencies` | `regencies.lookup` | Kabupaten/kota dalam provinsi |
| `GET /v1/regions/regencies/{regency_id}` | `regencies.lookup` | Detail kabupaten/kota |
| `GET /v1/regions/regencies/{regency_id}/districts` | `districts.lookup` | Kecamatan dalam kabupaten/kota |
| `GET /v1/regions/districts/{district_id}` | `districts.lookup` | Detail kecamatan |
| `GET /v1/regions/districts/{district_id}/villages` | `villages.lookup` | Desa/kelurahan dalam kecamatan |
| `GET /v1/regions/villages/{village_id}` | `villages.lookup` | Detail desa/kelurahan |
| `GET /v1/regions/postal-codes?province=...&regency=...&district=...&village=...` | `postal-codes.search` | Pencarian alamat hierarkis exact-match |
| `GET /v1/regions/postal-codes/{postal_code}` | `postal-codes.lookup` | Pencarian kode pos lima digit |

ID wilayah hanya berisi angka. Kode pos harus tepat lima digit. Pencarian kode pos mewajibkan empat parameter alamat (maksimal 150 karakter per parameter). Matching tidak peka kapitalisasi dan menerima awalan umum `Kota`, `Kabupaten`, `Kab.`, serta `Administrasi`. Hasil dapat memuat beberapa lokasi. Dataset kode pos di-host sendiri oleh Orvix dan berasal dari `sooluh/kodepos` berlisensi Apache-2.0; tidak ada request runtime ke layanan tersebut.

## NIK Parser Indonesia

NIK Parser Indonesia adalah parser struktur yang menjaga privasi untuk format 16 digit pada Nomor Induk Kependudukan Indonesia. Produk ini cocok untuk validasi form, normalisasi data, dan menjelaskan atribut yang dikodekan. API tidak menghubungi Dukcapil, mencari seseorang, membuktikan kepemilikan nomor, atau melakukan KYC.

- **Scope:** `nik:read` atau `api_store:all`
- **Harga:** gratis
- **Content type:** `application/json`

| Endpoint | Operasi | Keterangan |
|---|---|---|
| `POST /v1/nik/parse` | `nik.parse` | Parse struktur satu NIK 16 digit |
| `POST /v1/nik/parse-batch` | `nik.parse_batch` | Parse 1–100 NIK dengan urutan tetap |

```bash
export NIK="nilai-16-digit-anda"

curl https://api.orvix.id/v1/nik/parse \
  -X POST \
  -H "Authorization: Bearer $ORVIX_API_KEY" \
  -H "Content-Type: application/json" \
  --data "{\"nik\":\"$NIK\"}"
```

### Request tunggal

Body request hanya memiliki satu field:

```json
{
  "nik": "<16 digit ASCII>"
}
```

Response sukses memiliki bentuk berikut. Nilai di bawah hanya ilustrasi dan bukan contoh identitas atau NIK lengkap:

```json
{
  "data": {
    "structurally_valid": true,
    "provinsi": "NAMA PROVINSI",
    "kota_kabupaten": "NAMA KOTA / KABUPATEN",
    "kecamatan": "Nama Kecamatan",
    "birth": {
      "date": "2000-01-01",
      "formatted": "01 Januari 2000",
      "age": 26,
      "zodiac": "Capricorn",
      "is_birthday_today": false,
      "year_is_inferred": true,
      "year_inference": "rolling_century"
    },
    "gender": {
      "code": "L",
      "label": "Laki-laki",
      "symbol": "♂"
    },
    "issues": []
  },
  "meta": {
    "request_id": "01...",
    "product": "nik-parser-indonesia",
    "operation": "nik.parse",
    "source": {
      "name": "Indonesia administrative code legacy snapshot",
      "coverage": { "provinces": 34, "regencies": 514, "districts": 7230 },
      "authoritative": false
    },
    "pagination": null,
    "cache": null
  }
}
```

### Field response

| Field | Tipe | Arti |
|---|---|---|
| `structurally_valid` | boolean | `true` hanya jika tanggal dan ketiga tingkat wilayah dikenali secara struktural |
| `provinsi` | string atau `null` | Nama provinsi dari snapshot lokal |
| `kota_kabupaten` | string atau `null` | Nama kota atau kabupaten dari snapshot lokal |
| `kecamatan` | string atau `null` | Nama kecamatan dari snapshot lokal |
| `birth` | object atau `null` | Atribut kelahiran hasil interpretasi; `null` jika tanggal tidak valid |
| `birth.date` | string | Estimasi tanggal ISO (`YYYY-MM-DD`) |
| `birth.year_is_inferred` | boolean | Menandai bahwa tahun dua digit membutuhkan estimasi |
| `birth.year_inference` | string | Metode estimasi; saat ini `rolling_century` |
| `gender.code` | string | `L` atau `P`, hanya berdasarkan konvensi hari yang dikodekan |
| `issues` | array | Masalah struktur yang ditemukan tanpa menolak seluruh input berformat benar |

Tahun lahir memakai aturan rolling century: tahun dua digit yang tidak melebihi dua digit tahun saat ini ditempatkan pada 2000-an; selain itu ditempatkan pada 1900-an. Hasil ini adalah estimasi, bukan catatan kelahiran resmi.

### Request batch

Batch menerima 1–100 nilai dan mempertahankan urutan input:

```bash
curl https://api.orvix.id/v1/nik/parse-batch \
  -X POST \
  -H "Authorization: Bearer $ORVIX_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"niks":["<16 digit ASCII>","invalid"]}'
```

```json
{
  "data": [
    { "data": { "structurally_valid": true }, "error": null },
    {
      "data": null,
      "error": {
        "code": "nik_invalid_format",
        "message": "NIK must contain exactly 16 digits"
      }
    }
  ],
  "meta": {
    "product": "nik-parser-indonesia",
    "operation": "nik.parse_batch"
  }
}
```

Item tidak valid tidak menggagalkan item valid lainnya. Nilai duplikat diproses secara mandiri dan urutan tidak diubah.

### Masalah struktur dan status HTTP

| Kondisi | HTTP | Hasil |
|---|---:|---|
| `nik` tunggal tidak tersedia | 400 | `nik_required` |
| Nilai tunggal bukan tepat 16 digit ASCII | 400 | `nik_invalid_format` |
| `niks` batch tidak tersedia | 400 | `batch_required` |
| Batch berisi 0 atau lebih dari 100 item | 400 | `batch_too_large` |
| Kode provinsi, kota/kabupaten, atau kecamatan tidak dikenal | 200 | Data parsial, `structurally_valid: false`, dan item pada `issues` |
| Bulan atau hari yang dikodekan tidak valid | 200 | `birth: null`, `structurally_valid: false`, dan item pada `issues` |

Kode issue yang mungkin muncul meliputi `province_not_found`, `regency_not_found`, `district_not_found`, `invalid_month`, dan `invalid_day`. Setiap issue juga memiliki `field` yang menunjuk field response terkait.

### Privasi dan batasan

Response sengaja tidak memuat NIK yang dikirim, NIK tersamarkan, kode administrasi, atau nomor urut. NIK mentah tidak ditulis ke application log, activity log, analytics, maupun usage record. Metering hanya menyimpan metadata operasional seperti produk, operasi, status, dan latensi.

Parser tidak pernah menyatakan identitas benar-benar ada. Produk ini **bukan** layanan Dukcapil, verifikasi identitas, atau KYC. Snapshot legacy non-authoritative yang dibundel mencakup 34 provinsi, 514 kabupaten/kota, dan 7.230 kecamatan. Dataset belum mencakup empat provinsi Papua baru dan tidak boleh dianggap sebagai cakupan nasional yang lengkap atau terkini. Parsing NIK tidak melakukan network lookup saat request.

Input yang dapat diparse secara struktur mengembalikan HTTP 200. Tanggal atau kode wilayah yang tidak valid muncul di `data.issues`, membuat `structurally_valid` bernilai `false`, dan tetap mempertahankan data wilayah parsial yang tersedia. Format salah mengembalikan `nik_invalid_format`. Error per item batch tidak menggagalkan item valid lainnya.

## Indonesia Schools

`GET /v1/schools?page=1&size=20&search=Jakarta` memakai `schools.list`. `page` default 1 (maksimal 100.000), `size` default 20 (maksimal 100), dan `search` maksimal 100 karakter. Pagination berada di `meta.pagination`.

`GET /v1/schools/{npsn}` memakai `schools.detail`. NPSN harus tepat delapan huruf/angka ASCII. Sekolah yang tidak ditemukan mengembalikan `404` dan `not_found`.

## National Holidays

| Endpoint | Operation | Keterangan |
|---|---|---|
| `GET /v1/holidays?year=2026` | `holidays.list` | Hari libur untuk satu tahun |
| `GET /v1/holidays?year=2026&kind=cuti_bersama` | `holidays.list` | Filter `libur_nasional` atau `cuti_bersama` |
| `GET /v1/holidays/2026-12-25` | `holidays.check` | Periksa tanggal `YYYY-MM-DD` |
| `GET /v1/holidays/next?from=2026-10-01` | `holidays.next` | Libur pertama pada/setelah tanggal tersebut |

`year` harus 2000–2100. Tahun valid yang belum dipublikasikan mengembalikan `dataset_not_available`, bukan daftar kosong.

## BMKG Indonesia

| Endpoint | Operation | Cache |
|---|---|---|
| `GET /v1/bmkg/earthquakes/latest` | `bmkg.earthquakes` | 60 detik |
| `GET /v1/bmkg/earthquakes/felt` | `bmkg.felt` | 60 detik |
| `GET /v1/bmkg/weather?adm4=31.71.01.1001` | `bmkg.weather` | 1 jam; stale maksimal 6 jam saat upstream bermasalah |

`adm4` harus kode wilayah level empat numerik dengan empat bagian. Status cache tersedia di `meta.cache`.

## KBLI 2025

`GET /v1/kbli/categories` (`kbli.categories`), `GET /v1/kbli/codes` (`kbli.list`), dan `GET /v1/kbli/codes/{code}` (`kbli.detail`). Kode berisi 1–5 digit.

Parameter list: `page` default 1 (maksimal 10.000), `size` default 20 (maksimal 100), `level` 1–5, `parent` untuk kode induk, dan `q` maksimal 100 karakter.

## Kontrak sukses

```json
{
  "data": [],
  "meta": {
    "request_id": "01...",
    "product": "schools-indonesia",
    "operation": "schools.list",
    "source": null,
    "pagination": { "page": 1, "page_size": 20, "total_items": 123 },
    "cache": null
  }
}
```

`source`, `pagination`, dan `cache` selalu ada dan `null` jika tidak berlaku. Header `x-request-id` mengulang `meta.request_id`. Key eksternal dinormalisasi rekursif ke `snake_case`; value tidak diubah. Contoh: `Infogempa` menjadi `data.info_gempa`, `DateTime` menjadi `date_time`.

## Kontrak error

```json
{
  "error": { "code": "upstream_timeout", "message": "Region provider timed out" },
  "meta": {
    "request_id": "01...",
    "product": "regional-indonesia",
    "operation": "provinces.list",
    "upstream": { "classification": "timeout" }
  }
}
```

`meta.upstream` selalu ada dan `null` untuk validation, authentication, metering, dataset lokal, serta not-found. Klasifikasi upstream: `timeout`, `unavailable`, atau `invalid_response`. Body upstream mentah dan error internal tidak diekspos.

Code umum: `invalid_request_error`, `insufficient_balance`, `metering_error`, `not_found`, `dataset_not_available`, `dataset_error`, `upstream_timeout`, `upstream_unavailable`, dan `upstream_error`.

## Migrasi dari respons lama

- Baca record dari `data`, bukan root respons.
- Baca atribusi, pagination, dan cache dari `meta.source`, `meta.pagination`, dan `meta.cache`.
- Field pagination adalah `page`, `page_size`, dan `total_items`.
- Ganti `Infogempa`/`DateTime` menjadi `info_gempa`/`date_time`.
- Baca kegagalan dari `error.code` dan `error.message`; sertakan `meta.request_id` saat meminta bantuan.
